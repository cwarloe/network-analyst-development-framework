# Network Analyst Development Framework

Training material for network analysts working in cyber defense. It teaches the reasoning — how to frame a question, weigh evidence, hold competing explanations open, and hand off a judgment someone else can act on — through network subject matter rather than alongside it.

**All nine lessons now exist.** They are listed below and you can read them right now. None has been used by a learner yet — see the [roadmap](ROADMAP.md).

## The lessons

| | Lesson | What you do in it | Needs |
|---|---|---|---|
| 01 | **[What the analyst is for](lessons/01-what-the-analyst-is-for.md)** | Pull apart observation, interpretation, and judgment on three small cases | Nothing |
| 02 | **[Reading a conversation](lessons/02-reading-a-conversation.md)** | Narrate a real TCP+HTTP exchange from the packets, and separate "the connection worked" from "the request worked" | Capture + Wireshark |
| 03 | **[Names and expectations](lessons/03-names-and-expectations.md)** | Build a DNS baseline from real lookups, and find out how much normal looks like anomaly | Capture + Wireshark |
| 04 | **[What encryption hides](lessons/04-what-encryption-hides.md)** | Work out exactly where the visibility line falls in TLS 1.2 and TLS 1.3 | Capture + Wireshark |
| 05 | **[Vantage point and evidence](lessons/05-vantage-point-and-evidence.md)** | Build an evidence plan, and work out what your sources can't tell you | Nothing |
| 06 | **[When it breaks](lessons/06-when-it-breaks.md)** | Tell five faults apart from one user complaint, find out which aren't network problems, and meet the one that leaves no trace at all | Captures + Wireshark |
| 07 | **[When it's suspicious](lessons/07-when-its-suspicious.md)** | Argue the benign and the malicious reading of the same traffic before choosing between them | Capture + Wireshark |
| 08 | **[Judgment and handoff](lessons/08-judgment-and-handoff.md)** | Turn one analysis into a peer handoff and a manager summary | Nothing |
| 09 | **[Capstone — encrypted outbound traffic](lessons/09-capstone-encrypted-outbound-traffic/README.md)** | Work a full case, revise when new evidence lands, then transfer to an unrelated one | Nothing |

Lessons 01, 05, 08 and 09 need nothing at all — the case is supplied in the text. Lessons 02, 03, 04, 06 and 07 work against real packet captures in [`assets/pcaps/`](assets/pcaps/) and need Wireshark or `tshark`. Lesson 08 assumes 01–07, so it lands best with someone who already has some analysis or IT-ops background.

Start with **[lesson 01](lessons/01-what-the-analyst-is-for.md)**. It takes about 90 minutes and needs nothing but a text editor.

### About the captures

The captures are generated by [`lab/generate-captures.py`](lab/generate-captures.py) — real sockets, real public DNS resolvers, a real TLS stack — then rewritten into documentation address ranges. Every one is validated before it ships: **Wireshark must dissect it cleanly and Zeek must parse it into logs.** The Zeek check is the one that decides, because the target environment is Security Onion, where an analyst works in Hunt and Kibana and pivots to the packets only when the logs raise a question. A capture Zeek won't parse is invisible there, however good it looks in Wireshark. See [the lab README](lab/README.md).

The lessons show fields under the names **Security Onion actually indexes them** — `source.ip`, `connection.state`, `dns.query.name` — not the names Zeek writes. An analyst working a case never types `id.orig_h`. [`lessons/field-names.md`](lessons/field-names.md) is the mapping, taken from Security Onion's own ingest pipelines, for anyone running Zeek directly against the captures.

Two lessons declare known gaps rather than papering over them. **06** covers refused, dropped, reset, slow and fragment loss, but not packet loss or induced latency — those need traffic impairment the capture lab cannot produce without privileges. **07** uses lab-generated shapes rather than real adversary traffic; [R004](docs/research/R004-pcap-and-telemetry-sourcing.md) cleared the CIC and Stratosphere corpora for that, and it is the natural next step. Both lessons say so themselves. See the [roadmap](ROADMAP.md).

## Using this with a learner

Every lesson ends in a work product — a written assessment, a plan, a handoff — not a quiz. There are no scores, levels, or pass marks anywhere in this repository, deliberately: nothing here has been validated well enough to grade anyone.

**No lesson here has been used by anyone other than its author.** That is the single biggest gap in the project — bigger than any missing content. If you run one with someone, [`lessons/run-records.md`](lessons/run-records.md) covers which lesson to pick, how to sit in the room without wrecking the data, and what to write down.
