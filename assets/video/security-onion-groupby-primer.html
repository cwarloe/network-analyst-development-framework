Stacking means grouping events by a field and counting them. In Hunt, the groupby segment does it.
STEP 1Get a capture into Security Onion
  • 1Run so-import-pcap with the full path to the file. It needs an Import node, or another node with sensor services such as Eval or Standalone.
  • 2Security Onion generates alerts with Suricata and network logs with Zeek, and stores them with the original timestamps.
  • 3Or upload the pcap in Grid, and it runs the import for you.
Import one pcap per command if you want a link to each one.
STEP 2Open Hunt and set the time range
  • 1Click Hunt in the left menu.
  • 2The time picker starts at the last 24 hours. An imported capture is older, so you'd see nothing.
  • 3Set a time range that covers the date the capture was recorded.
  • 4Search event.dataset:conn.
Hunt is similar to Dashboards, so the same query bar and time picker apply.
STEP 3Stack one field
  • 1Add | and groupby and a field name to your search.
  • 2A Group Metrics table appears: the field, and a Count for each value.
Here the stack is the destination port: 40 records to port 53 and 21 to port 80.
STEP 4Stack two fields together
  • 1Put more than one field after groupby, separated by spaces.
  • 2You get one table with a column for each field, and one row per combination.
Destination IP and destination port together: four combinations in this capture.
STEP 5Sort rarest first
  • 1Click the Count heading to sort the table. Click again to flip the order.
  • 2Ascending puts the rarest combinations at the top. That's least-frequency analysis.
Rare isn't the same as bad.
A count tells you where to look first. It doesn't tell you what you found.
The rarest combination here appears once. What it means is still your call.
STEP 6Don't lose rows with missing values
A groupby leaves out events where the field is missing. Add an asterisk after the field name to keep them: network.protocol*. Failed connections often have no protocol at all, so they're exactly the rows you'd lose.
Capture from Lesson 06, which has failed connections. The blank row is the four that never got a protocol.

YOUR TURNTry it on your own capture
  • 1Import 07-suspicious.pcap into your Security Onion.
  • 2Set the time range to cover August 19, 2026.
  • 3Search event.dataset:conn | groupby destination.ip destination.port
  • 4Click Count to sort, then write down what you notice before you decide what it means.
  • 5Then load the Hunt data, using the Hunt data guide, and start Hunt 02.
Hunt 02 builds a stack like this as an Elasticsearch query. The Hunt data uses its own field names, such as user_agent.original. Imported captures use Security Onion's, such as http.useragent. Check the field list in your data before you copy a query.
